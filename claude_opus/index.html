Quant Primer — Concepts You'll Need

Qlib is a tool — but to use it well you need the mental model of systematic quantitative investing. This section is the crash course: every concept here maps directly to a Qlib API in the sections that follow.

1. The Quant Investment Loop

At its core, systematic quant follows one loop, repeated daily/weekly:

1
Raw Data
OHLCV, fundamentals
→
2
Features
Factors, signals
→
3
Model
Predict future returns
→
4
Strategy
Predictions → positions
→
5
Execution
Trade, measure, repeat

Qlib provides components for every step. The Data Layer handles (1)–(2), the ML Pipeline handles (2)–(3), the Backtester handles (4)–(5).

2. Alpha — What We're Actually Predicting

Alpha is excess return — the return your strategy earns above a passive benchmark (e.g. holding the index). Generating alpha means picking stocks better than random.

In Qlib, your model's output is interpreted as an alpha signal: a number per (stock, day) where higher = expect this stock to outperform. The absolute value doesn't matter — only the ranking across stocks on the same day.

Key intuition: Your model doesn't have to predict actual return percentages. It just has to sort stocks correctly. Stock A with predicted score 0.8 should outperform stock B with score 0.2 — even if both go down in absolute terms.

3. Features (Factors) — The Model's Inputs

A factor is any computable function of a stock's history that might predict future returns. Decades of academic research have produced a zoo of them:

Momentum
Return($close, 20)

Recent winners tend to keep winning over 1–12 months. The most robust anomaly in finance.

Reversal
−Return($close, 5)

Short-term (1–5 day) losers bounce back. Opposite sign to momentum at short horizons.

Volatility
Std(Return($close, 1), 20)

Lower-volatility stocks have historically earned higher risk-adjusted returns ("low-vol anomaly").

Volume
$volume / Mean($volume, 20)

Unusual volume signals attention, news, or institutional flow.

Value
B/P, E/P, S/P

Cheap stocks (low price relative to book/earnings) outperform long-term. Needs fundamentals data.

Quality
ROE, accruals

Profitable, well-run companies with clean accounting tend to outperform.

Qlib's Alpha158 handler bundles 158 such factors. You don't need to invent your own to start — but the magic happens when you do.

4. Labels — What We're Predicting Toward

The label is the future return your features try to predict. The standard Qlib label:

# "Predict tomorrow's return using today's features"
label = "Ref($close, -2) / Ref($close, -1) - 1"

Reading the expression: Ref($close, -1) is tomorrow's close (used to enter the position), Ref($close, -2) is the day-after close (exit). This is the return from holding the stock for one day, starting tomorrow.

Why -1 and -2, not 0 and -1? Because today's data (close, volume) isn't fully known until end-of-day. By the time you can act on the signal, you can only trade tomorrow's open or close. Trading on today's close-to-close return is impossible — that's look-ahead bias.

5. Cross-Sectional Thinking

Most quant models are cross-sectional: for each day, you rank all stocks in your universe by predicted alpha, then long the top decile and short the bottom decile (or just long the top, if shorting isn't available).

This is why Qlib normalizes labels with CSRankNorm — it converts raw returns to cross-sectional ranks within each day. The model learns to predict relative performance, not absolute returns. Absolute returns are dominated by market-wide noise that no model can predict.

❌ Time-series view
"Will AAPL go up tomorrow?"
Hard — too much noise, market regime dominates.
✅ Cross-sectional view
"Among 300 stocks tomorrow, which 30 will outperform the other 270?"
Tractable — relative ranking is more stable.

6. Information Coefficient (IC) — The Quant's North Star

How do you know if a signal is any good? IC is the rank correlation between your predictions and realized returns on each day.

# Conceptually: each day, compute Spearman correlation of (predictions, actual returns)
daily_ic = predictions.groupby("date").corr(actual_returns, method="spearman")
mean_ic  = daily_ic.mean()       # average daily IC
icir     = mean_ic / daily_ic.std()  # IC Information Ratio (consistency)
IC valueInterpretation
0.00Random — no predictive power
0.02Weak — borderline tradeable
0.05Strong — competitive with top hedge funds
0.10+Suspicious — likely a bug or data leak

ICIR measures whether the signal is consistent. An ICIR > 0.5 means your IC is reliably positive day after day — not just lucky in one regime.

7. From Predictions to a Portfolio

A prediction per stock is not yet a trade. A strategy converts predictions into positions. Qlib's default TopkDropoutStrategy works like this:

  1. Every rebalance day, rank all stocks by predicted alpha.
  2. You want to hold the top k stocks (e.g. top 50).
  3. From your current holdings, drop the n_drop lowest-ranked stocks (e.g. drop bottom 5).
  4. Buy n_drop new stocks from the top of the ranking that you don't already own.
  5. Hold equal-weighted positions in the resulting k stocks.

This trades only a fraction of the portfolio each day, which keeps transaction costs manageable. Alternative strategies: mean-variance optimization (Markowitz), risk-parity, factor-neutral long-short, etc.

8. Backtesting — Measuring Performance

A backtest simulates running your strategy on historical data. The output is a PnL curve and a set of metrics:

MetricWhat it tells you
Annualized ReturnCAGR of the strategy
Sharpe RatioReturn per unit of volatility (annualized). > 1 is good, > 2 is great.
Information Ratio (IR)Sharpe of excess return over benchmark. Measures skill, not market exposure.
Max DrawdownWorst peak-to-trough loss. Determines whether you can stomach the strategy.
TurnoverWhat fraction of the portfolio trades per day. High turnover = high cost sensitivity.
Win Rate / Hit RateFraction of days/trades that are profitable.

9. The Pitfalls (Read This Twice)

Bad quant research isn't just useless — it's actively dangerous. Every shiny backtest hides one of these:

🔮
Look-ahead bias
Using information not yet available at decision time. Classic example: normalizing features using statistics computed over the entire dataset (including future). Qlib's fit_start_time / fit_end_time exists exactly to prevent this.
⚰️
Survivorship bias
Backtesting only on stocks that exist today. Bankrupt or delisted stocks vanish from your universe, so your backtest only "sees" survivors — inflating returns. Qlib's CSI300 dataset is point-in-time, so members at each date reflect the actual index then.
💸
Ignoring transaction costs
A signal with 0.05 IC can have negative real-world returns if its turnover is too high. Always model commission, slippage, and (in China) stamp duty. Set open_cost, close_cost, min_cost in backtests.
🎯
Overfitting
Try 100 factor combinations on the same test set, pick the best — congrats, you've overfit. Always hold out a final test period you never look at until you're done iterating. Cross-validation alone isn't enough in time-series.
🌊
Regime change
A factor that worked 2010–2020 may stop working in 2022. Markets evolve. This is why Qlib has rolling training and the Online Manager — your model must refit periodically as the world changes.
📉
Capacity
A strategy that works on $1M may collapse at $100M because your trades move the market. Low-cap stocks especially have liquidity limits. Qlib's limit_threshold models price-limit hits in A-shares, but slippage modeling is on you.

Bottom line: Qlib is opinionated — it assumes you're doing cross-sectional alpha forecasting with daily rebalancing. That covers the vast majority of academic and quasi-institutional quant. For HFT, options, or pure portfolio optimization (no signal), you'll want different tools.

Installation

Qlib requires Python 3.8+ and can be installed via pip or from source. For GPU-accelerated models install PyTorch first.

# Install stable release
pip install pyqlib

# With all optional dependencies (pytorch models, RL, etc.)
pip install "pyqlib[all]"
git clone https://github.com/microsoft/qlib.git
cd qlib
pip install -e .          # editable install — changes reflected immediately

# Optional: install dev dependencies
pip install -e ".[dev]"
docker pull mcr.microsoft.com/qlib/qlib:latest

# Or build from the repo
cd qlib
docker build -t qlib .
docker run -it -v $(pwd):/workspace qlib bash
Note: On Apple Silicon (M1/M2) set QLIB_USE_NUMBA=0 if you hit compilation errors with Numba.

Qlib's data layer is its foundation. It stores market data in a binary columnar format optimized for fast time-series access.

Querying Data

from qlib.data import D

# ── Basic feature expression ──────────────────────────────────────────
# Closing prices for CSI300 stocks over a date range
df = D.features(
    instruments="csi300",
    fields=["$close", "$volume", "$open", "$high", "$low"],
    start_time="2020-01-01",
    end_time="2022-12-31",
    freq="day",
)
print(df.head())

# ── Feature engineering with Qlib operators ───────────────────────────
# All ops run server-side — blazing fast on 5000+ stocks
features = [
    "Ref($close, 1)",          # yesterday's close
    "Return($close, 1)",        # 1-day return
    "Mean($volume, 20)",        # 20-day average volume
    "Std($close, 20)",          # 20-day volatility
    "($close - $open) / $open", # intraday spread
    "Rank(Return($close, 5))",  # 5-day return rank cross-section
]
df = D.features("csi300", fields=features, start_time="2021-01-01", end_time="2022-01-01")
Tip: Qlib's expression engine is point-in-time safe. Ref($close, 1) at trading day T returns the close of T-1 — it never leaks future data.

Data Handler

DataHandlers are reusable preprocessing pipelines — normalization, missing-value fill, feature stacking — that run before the model sees the data.

from qlib.contrib.data.handler import Alpha158

handler = Alpha158(
    instruments="csi300",
    start_time="2008-01-01",
    end_time="2022-12-31",
    fit_start_time="2008-01-01",
    fit_end_time="2014-12-31",   # fit normalizers only on training data
)

# Retrieve prepared features
df = handler.fetch(col_set="feature")
print(df.shape)   # (n_days * n_stocks, 158)
Alpha158 is the classic 158-factor alpha set used in most Qlib papers. Alpha360 is a richer 360-factor version for deep learning models.

ML Pipeline — Dataset & Processors

A Dataset wraps a DataHandler and adds train/valid/test splitting and label generation. Processors apply per-split transformations.

Building a Dataset by Code

from qlib.data.dataset import DatasetH
from qlib.data.dataset.handler import DataHandlerLP
from qlib.data.dataset.processor import RobustZScoreNorm, Fillna, CSRankNorm

# Common processors
processors = {
    "feature": [
        {"class": "RobustZScoreNorm", "kwargs": {"fields_group": "feature", "clip_outlier": True}},
        {"class": "Fillna", "kwargs": {"fields_group": "feature"}},
    ],
    "label": [
        {"class": "CSRankNorm", "kwargs": {"fields_group": "label"}},   # cross-sectional rank
    ],
}

dataset = DatasetH(
    handler={
        "class": "Alpha158",
        "module_path": "qlib.contrib.data.handler",
        "kwargs": {
            "start_time": "2008-01-01",
            "end_time": "2022-12-31",
            "fit_start_time": "2008-01-01",
            "fit_end_time": "2014-12-31",
            "instruments": "csi300",
        },
    },
    segments={
        "train": ("2008-01-01", "2014-12-31"),
        "valid": ("2015-01-01", "2016-12-31"),
        "test":  ("2017-01-01", "2022-12-31"),
    },
)

df_train = dataset.prepare("train", col_set=["feature", "label"], data_key="learn")

Backtesting & Portfolio Analysis

Qlib's backtester simulates realistic trading: position limits, transaction costs, daily rebalancing. It then generates a full analytics report.

Running a Backtest

from qlib.contrib.evaluate import backtest_daily
from qlib.contrib.strategy import TopkDropoutStrategy

# Build strategy on top of model predictions
strategy_config = {
    "class": "TopkDropoutStrategy",
    "module_path": "qlib.contrib.strategy.signal_strategy",
    "kwargs": {
        "signal": (model, dataset),   # model + dataset → signals
        "topk": 50,                   # hold top-50 stocks
        "n_drop": 5,                  # replace 5 stocks each rebalance
    },
}

backtest_config = {
    "start_time": "2017-01-01",
    "end_time":   "2022-12-31",
    "account":     100_000_000,   # 100M CNY
    "benchmark":  "SH000300",    # CSI300 benchmark
    "exchange_kwargs": {
        "freq": "day",
        "limit_threshold": 0.095,  # 9.5% daily price limit (China)
        "deal_price": "close",
        "open_cost":  0.0005,      # 5 bps commission
        "close_cost": 0.0015,      # 15 bps (includes stamp duty)
        "min_cost":   5,
    },
}

portfolio_metric_dict, indicator_dict = backtest_daily(
    pred=predictions,
    strategy_config=strategy_config,
    executor_config={"class": "SimulatorExecutor",
                     "module_path": "qlib.backtest.executor",
                     "kwargs": {"time_per_step": "day", "generate_portfolio_metrics": True}},
    **backtest_config,
)

Full Workflow with MLflow Recorder

Qlib wraps MLflow to track experiments, save model artifacts, and reproduce results. Every run is automatically logged.

Complete End-to-End Script

import qlib
from qlib.constant import REG_CN
from qlib.utils import init_instance_by_config
from qlib.workflow import R
from qlib.workflow.record_temp import SignalRecord, PortAnaRecord, SigAnaRecord

# 1. Init
qlib.init(provider_uri="~/.qlib/qlib_data/cn_data", region=REG_CN)

# 2. Config
task = {
    "model": {
        "class": "LGBModel",
        "module_path": "qlib.contrib.model.gbdt",
        "kwargs": {"num_leaves": 31, "n_estimators": 100, "learning_rate": 0.05},
    },
    "dataset": {
        "class": "DatasetH",
        "module_path": "qlib.data.dataset",
        "kwargs": {
            "handler": {
                "class": "Alpha158",
                "module_path": "qlib.contrib.data.handler",
                "kwargs": {
                    "start_time": "2008-01-01", "end_time": "2022-12-31",
                    "fit_start_time": "2008-01-01", "fit_end_time": "2014-12-31",
                    "instruments": "csi300",
                },
            },
            "segments": {
                "train": ("2008-01-01", "2014-12-31"),
                "valid": ("2015-01-01", "2016-12-31"),
                "test":  ("2017-01-01", "2022-12-31"),
            },
        },
    },
}

model   = init_instance_by_config(task["model"])
dataset = init_instance_by_config(task["dataset"])

# 3. Run experiment — everything inside R.start() is tracked
with R.start(experiment_name="lgb_csi300"):
    # Log hyperparams
    R.log_params(**{"num_leaves": 31, "lr": 0.05})

    # Train
    model.fit(dataset)
    R.save_objects(**{"model.pkl": model})

    recorder = R.get_recorder()

    # Signal records (predictions + IC analysis)
    sr = SignalRecord(model, dataset, recorder)
    sr.generate()

    sar = SigAnaRecord(recorder)
    sar.generate()

    # Portfolio analysis (backtest)
    par = PortAnaRecord(recorder, port_analysis_config, "day")
    par.generate()

print("Experiment saved. Browse with: mlflow ui --backend-store-uri mlruns")

Online Serving & Rolling Updates

In production, market dynamics shift over time. Qlib's online module handles automatic model rolling, concept drift detection, and serving predictions.

Rolling Training

from qlib.model.trainer import TrainerR
from qlib.workflow.online.strategy import RollingStrategy

# Roll the model forward every quarter
rolling_config = {
    "step": 20,                 # refit every 20 trading days
    "rtype": "expanding",       # or "rolling" for a sliding window
    "train_start": "2008-01-01",
    "train_end":   "2022-12-31",
}

# Use qrun with rolling_train.yaml or the API:
from qlib.model.trainer import task_train
from qlib.workflow import R

with R.start(experiment_name="rolling_lgb"):
    task_train(task_config, dataset)   # trains one fold

Online Manager

from qlib.workflow.online.manager import OnlineManager
from qlib.workflow.online.strategy import RollingStrategy

# OnlineManager orchestrates model serving and rollover
strategy = RollingStrategy(
    experiment_name="rolling_lgb",
    rolling_step=20,
)

om = OnlineManager(strategy)
om.routine()     # called once per day in a scheduler (cron, Airflow, etc.)
Production pattern: Run om.routine() daily via cron or Airflow. It checks whether a new fold needs training, trains if so, and seamlessly switches to the new model.

Tips & Common Gotchas

⚠️
Look-ahead bias
Always set fit_start_time / fit_end_time on your handler to match your training split. Fitting normalizers on all data leaks future statistics into training.
💾
Data download takes time
The CSI300 daily dataset is ~400 MB. Run GetData().qlib_data(...) once, then point qlib.init() at the cached directory on every subsequent run.
🔧
Feature expression typos
Field names are case-sensitive and prefixed with $. Use $close, not $Close. Qlib will silently return NaN for unknown fields in some versions.
📉
Transaction cost matters
In China A-shares, stamp duty + commission can be 20–25 bps round-trip. Always set open_cost and close_cost in your backtest config — ignoring costs overstates returns significantly.
🔄
Reproducibility
Set seeds for PyTorch and NumPy before model init. Use R.get_recorder().load_object("model.pkl") to reload a saved model exactly.
📦
Module path format
Qlib resolves classes dynamically via module_path + class. This means you can drop any class implementing the right interface into a YAML config without modifying Qlib source.
