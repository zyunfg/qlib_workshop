Qlib × Polymarket

A staged plan for treating prediction-market outcome tokens as a first-class asset class inside Microsoft Qlib's ML quant pipeline.

Qlib Polymarket CLOB Custom Provider LightGBM Paper → Live

Why bother?

Polymarket exposes thousands of binary outcome tokens, each priced between 0 and 1 like an implied probability. The data shape (price history, volume, liquidity) looks like equities, but the semantics — bounded prices, hard resolution dates, complementary YES/NO pairs — break most of equity quant's assumptions. Qlib is the right framework to plug into because:

🔌

Pluggable layers

Qlib's BaseProvider, DataHandler, Model, and Strategy are all swappable. We don't fork anything — we subclass.

🧮

Expression DSL

$prob, Ref($prob, 1), Mean($vol, 20) — Qlib's symbolic features work on any column, not just OHLCV.

📊

Cross-sectional ranking

Polymarket's natural alpha is relative mispricing across markets in a category. Qlib's universe / cross-sectional norm is exactly this shape.

🔁

Rolling retrain

Markets resolve constantly. Qlib's OnlineManager + RollingStrategy handles a universe that's churning every week.

The thesis in one line: Polymarket's price action contains the same momentum/mean-reversion/liquidity signatures as equities, plus market-specific structural alpha (complementary pairs summing > 1, time-decay before resolution). Qlib's ML pipeline can surface this systematically if we adapt the data layer.

Domain mapping: Equities → Prediction markets

The integration is mostly a vocabulary translation. Get this table right and everything downstream follows.

Qlib conceptEquity worldPolymarket equivalent
InstrumentStock ticker (AAPL)Outcome token ID (YES on "Will X happen by Y?")
UniverseS&P 500, CSI300Live markets in a category (e.g. Politics-US-2028)
CalendarNYSE trading days24/7 with hourly or daily bars
OHLCVOpen/High/Low/Close, VolumeBucketed mid-price OHLC + traded volume + book depth
Return(P_t − P_{t−1}) / P_{t−1}Same, but bounded; consider logit(P_t) − logit(P_{t−1})
LabelForward N-day return, rankedForward N-hour prob change, or P(resolution=YES) − current_price
Listing/DelistingIPO / delistingMarket creation / resolution (very frequent)
DividendsCash + adjustmentsNone — but resolution = full payout to one side
Cross-sectionRank across stocksRank within market category, or across complementary pairs
Key insight: bounded prices make linear features misleading. Always work in logit space (log(p/(1−p))) when computing momentum, vol, and z-scores. Linear differences on prices near 0 or 1 over-react.

Polymarket surface area

Three endpoints carry 95% of what we need. None require auth for read-only ingest; writes need an API key + Polygon wallet.

Gamma API

Market metadata

gamma-api.polymarket.com — list active markets, categories, end-dates, token IDs, slugs. The "universe builder" endpoint.

CLOB API

Order book + trades

clob.polymarket.com — live order book, recent trades, place/cancel orders. Use the py-clob-client SDK.

Prices History

Time series

clob.polymarket.com/prices-history — historical midpoint price series per token at chosen intervals (1m/1h/6h/1d). This is our OHLCV substitute.

Subgraph (Polygon)

Resolution events

Polygon subgraph queryable via GraphQL — gold for resolution truth labels and on-chain event reconstruction.

Phase 1 · Data ingestion

Goal: write Polymarket history into Qlib's binary format so existing tools just work.

  1. Universe builder. Poll Gamma daily, persist instruments/politics.txt with rows <token_id> <start_date> <end_date> — same schema as ~/.qlib/qlib_data/us_data/instruments/csi300.txt.
  2. Loader. For each instrument, fetch prices-history at the chosen interval. Bucket trades into OHLCV-shaped bars (Open/High/Low/Close come from intra-bucket ticks; "volume" = sum of traded notional).
  3. Augmenters. Add Polymarket-specific columns: $bid, $ask, $mid, $depth_bid, $depth_ask, $tte_days (time-to-expiry), $pair_sum (YES+NO sum).
  4. Writer. Use qlib.tests.data.GetData as a reference and call qlib.utils.dump_bin per column. Output structure matches qlib's expectations: 
    ~/.qlib/qlib_data/polymarket/
  ├── calendars/{1d.txt, 1h.txt}
  ├── instruments/{all.txt, politics.txt, crypto.txt}
  └── features/<token_id>/{close, volume, mid, bid, ask, ...}.day.bin
# ingest/loader.py — skeleton
import pandas as pd, requests
from datetime import datetime, timedelta

def fetch_bars(token_id: str, interval="1h", days=180) -> pd.DataFrame:
    r = requests.get(
        "https://clob.polymarket.com/prices-history",
        params={"market": token_id, "interval": interval, "fidelity": 60},
        timeout=30,
    ).json()
    df = pd.DataFrame(r["history"])
    df["datetime"] = pd.to_datetime(df["t"], unit="s")
    df = df.set_index("datetime")["p"].rename("mid").to_frame()
    # OHLC from ticks; if API gives only mid-points, OHLC ≈ mid
    df["open"] = df["high"] = df["low"] = df["close"] = df["mid"]
    df["volume"] = 0  # backfill from CLOB trades endpoint
    return df
Storage note: Qlib's bin format is per-column, float32, with one row per calendar entry. Pre-resolution dates write the bar; post-resolution dates write NaN. The DataHandler will mask these out.

Phase 2 · Custom Provider + Handler

Goal: teach Qlib to read our bin store and expose Polymarket-shaped expressions.

Two narrow extensions to Qlib:

# qlibx/polymarket/provider.py
from qlib.data.data import LocalProvider

class PolymarketProvider(LocalProvider):
    """Same on-disk layout as LocalProvider, but knows about
    instrument churn (markets that resolve are 'delisted')."""

    def list_instruments(self, instruments, start_time=None,
                         end_time=None, as_list=False):
        # Filter to markets that are LIVE during the window.
        # A resolved market on 2026-04-01 should not appear
        # in any feature row dated 2026-04-15.
        df = super().list_instruments(instruments, start_time, end_time, True)
        return [(tok, s, e) for tok, s, e in df if s <= end_time and e >= start_time]
# qlibx/polymarket/handler.py
from qlib.contrib.data.handler import DataHandlerLP
from qlib.data.dataset.processor import RobustZScoreNorm, Fillna, CSRankNorm

class PolymarketHandler(DataHandlerLP):
    def get_feature_config(self):
        # All expressions evaluated in logit-space where price is involved
        fields = []
        names = []
        # Momentum on logit-prob
        for k in [1, 6, 24, 72, 168]:   # in hours
            fields.append(f"Log($close/(1-$close)) - Ref(Log($close/(1-$close)), {k})")
            names.append(f"LOGIT_MOM_{k}")
        # Realized vol of logit-returns
        for k in [24, 72]:
            fields.append(f"Std(Log($close/(1-$close)) - Ref(Log($close/(1-$close)),1), {k})")
            names.append(f"LOGIT_VOL_{k}")
        # Liquidity / book pressure
        fields += ["$volume/Mean($volume, 168)", "($ask-$bid)/$mid", "$depth_bid/($depth_bid+$depth_ask)"]
        names  += ["VOL_SURGE", "REL_SPREAD", "BOOK_IMBAL"]
        # Time-to-expiry decay
        fields.append("$tte_days")
        names.append("TTE")
        # Pair coherence (sum of YES+NO; arbitrage if >1)
        fields.append("$pair_sum - 1")
        names.append("PAIR_GAP")
        return fields, names

    def get_label_config(self):
        # Forward 1-day logit-return — direction + magnitude
        return ["Ref(Log($close/(1-$close)), -24) - Log($close/(1-$close))"], ["LABEL0"]

    region="custom",

    freq="1h",

Phase 3 · Feature engineering

Goal: factors that exploit prediction-market structure, not just equity-style momentum.

Logit momentum

Δ logit(p) over 1h, 6h, 1d, 1w. Bounded-price-safe replacement for log return.

Realized vol (logit space)

Rolling std of 1-step logit returns. High vol = uncertain narrative.

Pair-sum arbitrage

price(YES) + price(NO) − 1. Persistent positive = liquidity-providing edge.

Time-to-expiry decay

Probability variance compresses as TTE → 0. Strong interaction feature with vol.

Book imbalance

bid_depth / (bid_depth + ask_depth) at top-of-book. Short-horizon directional.

Spread compression

Falling (ask − bid)/mid predicts increased trading attention.

Cross-market drift

Beta of this market to its category index (politics, crypto, sports).

News surprise proxy

Joint spike in volume + spread blowout + logit jump. Captures event windows.

Cross-sectional norm by category, not globally. A 1-σ move in a high-vol crypto market is not comparable to a 1-σ move in a sports market. Use CSRankNorm with group_by="category".

Phase 4 · Model

Goal: predict 1-day forward logit-return; convert to expected dollar edge per token.

Phase 5 · Backtest

Goal: walk-forward simulation that correctly accounts for resolution payoffs and CLOB frictions.

Qlib's TopkDropoutStrategy doesn't quite fit — it assumes continuous holdings. We need a thin wrapper:

1

Score → edge

Convert predicted Δ logit to expected price change. Filter to abs(edge) > 2× round-trip cost.

→
2

Size by Kelly fraction

Cap at 5% of bankroll per market; cap aggregate at 25% per category to avoid correlated blow-ups.

→
3

Resolution settle

On expiry date, all positions resolve to 0 or 1 instantly. PnL = (resolution − entry) × size.

→
4

Cost model

Use simulated taker fills against book snapshot + gas (~$0.01 on Polygon). Slippage = walk-the-book.

# qlibx/polymarket/strategy.py
from qlib.strategy.base import BaseStrategy

class PolymarketEdgeStrategy(BaseStrategy):
    def __init__(self, signal, min_edge=0.015, kelly_cap=0.05, **kw):
        super().__init__(**kw)
        self.signal = signal
        self.min_edge = min_edge      # 1.5% expected price change
        self.kelly_cap = kelly_cap

    def generate_trade_decision(self, execute_result=None):
        scores = self.signal.get_signal(start=self.trade_calendar.now(), end=...)
        # scores are predicted Δ logit; convert to Δ price
        for token, dlogit in scores.items():
            p = self._book_mid(token)
            d_price = p*(1-p) * dlogit           # delta-method
            if abs(d_price) < self.min_edge: continue
            side = "BUY_YES" if d_price > 0 else "BUY_NO"
            size = min(self.kelly_cap, abs(d_price)/0.10) * self.bankroll
            yield self._order(token, side, size)

Phase 6 · Live execution

Goal: same code path as backtest, with a CLOB executor in place of the simulator.

  1. Auth setup. EOA on Polygon, USDC.e for collateral, API key + secret + passphrase via Polymarket's signing flow (L1 → L2 derived key). Stash in env vars, never in repo.
  2. Executor. Subclass Qlib's BaseExecutor. execute() takes the strategy's order list and calls py-clob-client's create_and_post_order with GTC limit at top-of-book or post-only one tick inside.
  3. Order monitoring. Background task polls open orders; cancel after max_age_seconds if unfilled. Update Qlib's position tracker on fills.
  4. Kill switches. Hard limits on (a) max daily drawdown, (b) max position per market, (c) total bankroll deployed. Trip → cancel-all + halt.
  5. Reconciler. Hourly: read on-chain balances via Polygon RPC, reconcile against Qlib's internal book. Mismatch → halt + alert.
from py_clob_client.client import ClobClient
from py_clob_client.clob_types import OrderArgs, OrderType

class PolymarketExecutor:
    def __init__(self, host="https://clob.polymarket.com", **creds):
        self.cli = ClobClient(host, **creds)
        self.cli.set_api_creds(self.cli.create_or_derive_api_creds())

    def execute(self, decision):
        for o in decision.orders:
            args = OrderArgs(
                token_id=o.token,
                price=o.limit_price,
                size=o.size_shares,
                side="BUY" if o.is_long else "SELL",
            )
            signed = self.cli.create_order(args)
            resp = self.cli.post_order(signed, OrderType.GTC)
            yield resp
Geography: Polymarket's TOS restricts US persons from trading. Run live only from a jurisdiction where the platform is available, and confirm independently — this plan does not constitute legal or regulatory advice.

Risks & gotchas

⚠️ Will bite you

  • Resolution oracle disputes. UMA-resolved markets can take days to finalize and occasionally get re-litigated. Mark these as illiquid until settled.
  • Survivorship in training data. If you only train on resolved markets, you over-fit to "tradable until the end" — include cancelled/illiquid markets with appropriate masking.
  • Label leakage at resolution. A market that resolves YES at 4pm UTC will have price → 1 minutes before. Always embargo the last N hours of data per market.
  • Pair-arb illusion. YES + NO sums > 1 often reflect liquidity cost, not free money. Net of fees the edge frequently vanishes.
  • Adverse selection. Resting limit orders fill when news arrives. Aggressive sizing on limits = systematically wrong side of every event.

🛡️ Mitigations

  • Filter universe to markets with daily volume > $5k and TTE > 24h. Eliminates ~70% of long tail, keeps the signal-rich head.
  • Logit-space everything. Stops the framework from over-weighting extreme-price markets where 0.99 → 0.999 looks like a 1% move but is 2.3 in logit.
  • Walk-forward backtest, no peeking. Refit weekly, never lookahead. Embargo resolution windows.
  • Paper-trade for 4 weeks min. Live spreads + fill rates ≠ backtest assumptions; this is the #1 failure mode.
  • Start tiny. 1% bankroll allocation for the first month. Scale only after live IC ≥ backtest IC.
