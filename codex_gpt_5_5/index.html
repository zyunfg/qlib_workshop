Beginner Quant Primer

Quant investing is not just "predict the stock price." It is a disciplined process for making decisions under uncertainty: define what can be traded, compute signals from data available at the time, convert those signals into a portfolio, and test whether the result survives costs, risk, and honest out-of-sample evaluation.

1. The real object is a portfolio decision

A quant model usually predicts a score, not a guaranteed price. The trading system must still decide which assets to hold, how much capital to allocate, when to rebalance, and what to compare against. In Qlib, strategy and backtest are as important as model.

Instrument
A tradable asset, such as one stock. Example: SH600000.
Universe
The allowed trading list. Example: csi300.
Benchmark
The reference you try to beat, such as an index.

2. Prices become returns and risk

Raw prices are hard to compare across assets. Quant research often studies returns: how much an asset changed over a period. Risk is not just "losing money"; it includes volatility, concentration, drawdown, and exposure to a market index or sector.

Return
Percentage change in value, often measured daily or over a future horizon.
Volatility
How unstable returns are. Higher volatility means a bumpier ride.
Drawdown
The fall from a portfolio peak to a later low.

3. Features are questions you ask the data

A factor is a numeric question about the market: has price been rising, is volume unusual, is the stock cheap relative to peers? Qlib calls these feature expressions. A label is the future value you want to predict, usually a future return.

OHLCV
Open, high, low, close, and volume.
Feature or factor
An input signal such as five-day return or moving average.
Label
The target, such as next-period return.

4. Alpha means useful signal, not magic

Alpha is excess value beyond a benchmark after realistic costs and constraints. A signal can look good before costs and fail after turnover, slippage, or crowded trades. Treat alpha as a hypothesis that must be stress-tested.

Signal
A model score or factor value used to rank assets.
Turnover
How much the portfolio changes each rebalance.
Transaction cost
Fees, taxes, bid-ask spread, and slippage from trading.

5. Time order is sacred

Finance data is time ordered. You cannot train on the future and pretend you discovered a real signal. Split data chronologically: train on earlier dates, validate on later dates, and test on the final unseen period.

Look-ahead bias
Using information that would not have been known at trade time.
Data leakage
Any path where test-period information sneaks into training or feature design.
Out-of-sample
Performance measured on data not used to fit or tune the strategy.

6. Backtests are simulations, not evidence by themselves

A backtest answers "what would this rule have done on this historical data?" It can be distorted by unrealistic execution, missing delisted assets, repeated tuning, or choosing the best result from many failed experiments.

Overfitting
Fitting noise in the past instead of learning a pattern likely to repeat.
Slippage
The difference between expected and actual execution price.
Walk-forward test
Repeatedly train on a past window, test on the next future window, then roll forward.

Read any Qlib workflow like this

  1. Data: Which market, dates, instruments, and fields are allowed?
  2. Features: What information is computed before the prediction time?
  3. Label: What future outcome is the model trying to predict?
  4. Model: How are features converted into ranking scores?
  5. Strategy: How do scores become holdings and trades?
  6. Backtest: Are costs, constraints, turnover, and benchmark comparison included?
  7. Review: Would the result still be credible on a different period or universe?

Beginner trap: predicting price level

Most equity models predict returns or rankings, because raw price levels are not comparable across stocks.

Beginner trap: trusting one great chart

A smooth backtest can come from overfitting. Ask how many variants were tried before this one was selected.

Beginner trap: ignoring costs

Small predictive edges can disappear if the strategy trades frequently or assumes impossible execution.

Hands-on Labs

Each lab has a concrete output, beginner definitions, and a short quant concept to debrief.

Lab 1: Initialize Qlib and inspect market data

Goal: load a trading calendar, an index universe, and raw OHLCV fields.

Terms in this lab: provider_uri is the folder where Qlib data lives. calendar is the list of trading days. instruments are the stocks you can trade. 
python - <<'PY'
import qlib
from qlib.constant import REG_CN
from qlib.data import D

qlib.init(provider_uri="~/.qlib/qlib_data/cn_data", region=REG_CN)
print(D.calendar(start_time="2017-01-01", end_time="2017-01-10", freq="day")[:5])
inst = D.instruments(market="csi300")
print(D.list_instruments(inst, start_time="2017-01-01", end_time="2017-01-10", as_list=True)[:10])
print(D.features(["SH600000"], ["$open", "$close", "$volume"], start_time="2017-01-01", end_time="2017-01-10").head())
PY

Debrief: before modeling, you must know exactly which assets, dates, and fields your research is allowed to use.

Lab 2: Build feature expressions

Goal: create small alpha-style features and inspect their values before modeling.

Terms in this lab: Ref($close, 1) means yesterday's close. Mean($close, 5) means five-day average close. A factor is useful only if it is known before the prediction target happens. 
python - <<'PY'
import qlib
from qlib.constant import REG_CN
from qlib.data import D

qlib.init(provider_uri="~/.qlib/qlib_data/cn_data", region=REG_CN)
fields = [
    "$close",
    "Ref($close, 1)",
    "Mean($close, 5)",
    "($close - Ref($close, 5)) / Ref($close, 5)",
    "$high - $low",
]
df = D.features(["SH600000"], fields, start_time="2017-01-01", end_time="2017-02-01")
print(df.tail(10))
PY

Debrief: factors are testable hypotheses. Look for data leakage, alignment, missing values, and economic meaning before training.

Lab 3: Run a LightGBM research workflow

Goal: use Qlib's configuration interface to train a model and generate prediction records.

Terms in this lab: LightGBM is a tree-based machine learning model. Alpha158 is a predefined Qlib feature set. qrun executes a full workflow from a YAML config. 
cd qlib
qrun examples/benchmarks/LightGBM/workflow_config_lightgbm_Alpha158.yaml

Debrief: Qlib separates research into repeatable parts: dataset, model, recorder, signal analysis, and portfolio analysis.

Lab 4: Read the backtest outputs

Goal: connect predictions to a TopK-Dropout strategy and interpret the portfolio report.

Terms in this lab: TopK means buying the highest-ranked predictions. Dropout means replacing only part of the portfolio each period. A backtest report should be judged after trading costs, drawdowns, and benchmark comparison. 
cd qlib
find mlruns -maxdepth 4 -type f | sort | tail -50
python examples/workflow_by_code.py

Debrief: model metrics are not enough. Inspect turnover, transaction costs, drawdown, benchmark-relative return, and date-range robustness.
